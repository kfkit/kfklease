kfklease

Distributed leases and leader election on top of Apache Kafka®.

A single-writer lease derived from a compacted Kafka topic, plus a KEDA external scaler that runs a workload in exactly one cluster at a time and fails it over when that cluster goes away. No extra coordination service: if your services already share a Kafka cluster, they already have an arbiter.

Status

Early development. The protocol, the Go API and the chart are still moving, and nothing is tagged for release yet. Useful to read and to try on a test cluster — not yet something to put in front of production traffic.

What is here

  • lease/ — the protocol as a dependency-free state machine, and a Kafka-backed candidate.
  • scaler/, cmd/kfklease-scaler — a KEDA external-push scaler over that lease.
  • charts/kfklease — a Helm chart to deploy the scaler per cluster.
  • test/e2e/ — a two-cluster stand exercising cold start, crash, partition and pause.

A caveat worth stating up front

This gives you failover, not strict mutual exclusion. KEDA scales a workload down, but it cannot promise the old instance has stopped before the new one starts. Where correctness depends on a single writer, fence at the resource using the lease epoch.
